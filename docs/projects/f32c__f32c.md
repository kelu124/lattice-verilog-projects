Scope of this page: the f32c CPU core and the ULX3S SoC targets under
`rtl/proj/lattice/ulx3s/`, plus the SoC peripherals worth reusing elsewhere.
The repo also targets Xilinx, Altera/Intel and several non-ULX3S Lattice
boards (`rtl/xilinx`, `rtl/altera`, `rtl/lattice/{brevia,ffm-lfe5u,
fleafpga_ohm,fleafpga_uno,icoboard_beta,kondor_ax,mmm_v4r0,sparrowhawk,
ulx2s}`) and a large software tree (`src/`: C runtime, compiler, bootloader,
examples, benchmarks) — both are out of scope here and not reviewed.

## What the gateware does

- **f32c CPU core**: retargetable, scalar, pipelined 32-bit soft processor
  that executes a subset of either RISC-V (RV32) or MIPS (MI32), selected by
  the `C_arch` generic. Top entity `f32c_core` (`rtl/cpu/f32c_core.vhd`),
  1794 lines, optional branch predictor, direct-mapped I/D caches, exception
  handling, single-step debug port. Per `README.md`: 3.3 CoreMark/MHz from
  BRAM, up to ~185 MHz Fmax on 6-input-LUT FPGAs (unverified: README claim,
  not confirmed for ECP5/ULX3S specifically here).
- **ULX3S SoC integration** (`rtl/proj/lattice/ulx3s/`, 17 build directories):
  each variant picks one pre-built `TOP_MODULE_FILE` from
  `rtl/lattice/ulx3s/top/*.vhd` (28 top files) that wires the CPU to a
  peripheral set — video output flavor, SDRAM vs BRAM, self-test, etc. See
  Structure below for the mapping.
- **SDRAM-backed general-purpose SoC** (`xram_sdram_normal`,
  `xram_sdram_synth`, `xram_sdram_text`, `xram_sdram_tvfm`, `xram_sdram_433`,
  `xram_sdram_lvds`, `xram_sdram_noflash`): CPU + external SDRAM + video +
  UART + SPI flash/SD, the general-purpose configuration people build for.
- **Board self-test** (`xram_sdram_selftest`, top
  `top_ulx3s_12f_xram_sdram_selftest.vhd`, constraints
  `ulx3s_options/ulx3s_v20_selftest.lpf`): this is the design behind the
  `f32c/` bitstream shipped in `emard/ulx3s-bin`, confirmed by matching
  project name `f32c_selftest_2ws_89mhz` in
  `rtl/proj/lattice/ulx3s/xram_sdram_selftest/makefile`.
- **BRAM-only SoC** (`bram/`, Diamond `.ldf` project only — no local
  makefile/top source in this pruned checkout; `bram_trellis/` is the
  (broken) open-flow attempt at the same target).
- **SoC peripheral library** (`rtl/soc/`, per `rtl/soc/README.md`): multiport
  SRAM/SDRAM/AXI/DDR3 memory controllers, floating-point vector processor,
  2D video accelerator (windows/sprites/textmode/scroll/blitter) with
  HDMI/VGA/composite/LED-strip output, 16-bit stereo PCM DMA audio, a
  128-voice tonewheel synth, SPDIF and analog PWM audio out, an 88–108 MHz
  FM/RDS transmitter, a 433.92 MHz ASK transmitter, a PID motor controller,
  timer/GPIO/SPI/UART, USB 1.1 device (serial/CDC), PS/2, and an RTC.

## How to build

Not run (per task scope: no make/build). From reading the makefiles:

```sh
cd rtl/proj/lattice/ulx3s/xram_sdram_normal
make            # Diamond synth+PAR via diamond_main.mk, needs $DIAMOND_BASE
make prog       # fujprog <bitstream>.bit, load over US1 JTAG
make flash      # fujprog -j flash <bitstream>.bit, permanent
```
Requires Lattice Diamond installed and `DIAMOND_BASE` pointing at it
(`rtl/proj/lattice/include/scripts/diamond_path.mk`, not read in detail).
`FPGA_SIZE`/`CONSTRAINTS`/`TOP_MODULE_FILE` are chosen per variant inside
each `makefile` (see table above); switching board revision means
uncommenting a different `CONSTRAINTS` line.

The open-flow path (`bram_trellis`, `xram_sdram_normal_trellis`) uses
`yosys -m ghdl -q synth.ys` + `nextpnr-ecp5 --router router2` + `ecppack`,
but both are marked non-working by their own `README.md`.

Notes on dropping these into a new ULX3S design:
- **Clock/reset**: most blocks take a plain `clk`/`reset` plus a
  `C_clk_freq` generic in Hz (e.g. `spdif_tx`, `ps2`, `cvbs`) — any system
  clock works, no PLL dependency baked in. The CPU core (`f32c_core`) is
  itself clock-generic; the SoC top files instantiate Diamond-SCUBA PLL
  netlists per configuration (`rtl/lattice/ulx3s/clocks/*.vhd`, e.g.
  `clk_25_100_125_25.vhd`, header: "VHDL netlist generated by SCUBA Diamond
  (64-bit) 3.7.0.96.1") — these are **Diamond-only IP** (ECP5U primitive
  library), not portable to the open flow without regenerating with
  `ecppll`/`nextpnr` equivalents.
- **DVI/TMDS**: `vga2dvid.vhd` itself is pure behavioral VHDL and portable;
  only the DDR output stage (`ddr_dvid_out_se.vhd`) is ECP5-specific
  (`ODDRX1F` via `ddr_out`), and that wrapper already targets ECP5U so it
  should carry over directly on another ULX3S design.
- **SDRAM controller**: generic 16-bit SDR SDRAM interface
  (`sdram_address_width`, `sdram_column_bits`, `sdram_startup_cycles`,
  `cycles_per_refresh` generics), not ULX3S-pin-specific — the multi-port
  arbiter (`C_ports` generic) is the part worth lifting for a new design.
- **USB device**: `usb_serial.vhd` needs a UTMI-style 8-bit PHY; this repo
  supplies its own soft PHY (`usb11_phy/`, OpenCores-derived, see license
  caveat above) rather than a hard UTMI transceiver, so the pair reuses as a
  unit.
- **Pin/LPF reuse**: this repo already targets ULX3S with
  `ulx3s_v20.lpf`/`ulx3s_v17patch.lpf`/`ulx3s_options/*` in
  `rtl/proj/lattice/constraints/`, so pin names for a new ULX3S design built
  from these blocks should carry over directly; only clock-frequency
  generics need adjusting per target board revision.
- The **emard "universal make" pattern** referenced in
  `.claude/memory/reusable-cores.md` (`trellis_main.mk`/`diamond_main.mk`,
  `FPGA_SIZE=12|25|45|85`) is present here too as
  `rtl/proj/lattice/include/scripts/diamond_main.mk` /
  `rtl/proj/lattice/ulx3s/universal_make/files.mk`, confirming the
  "Diamond-only historical ports" line in that file for f32c.

  was only skimmed; useful reading before wiring a new peripheral to
  `f32c_core`.
